## Why

A prompt worth writing carefully outlives the tab it was typed in. Paseo's existing draft storage is the composer's: keyed to a draft agent tab, finalized records expire after five minutes, and clearing one blanks the text. There is nowhere to keep an instruction you are still refining, no way to send the same instruction to a second agent, and no record of what you actually asked for three revisions ago.

A working implementation of exactly this already exists on `fotile96/paseo` branch `feat/drafts` (head `6a990f412`, Apache 2.0, same upstream). Its branch point is `d4841b68f` (2026-09-02), sixty commits behind this fork's head. A trial merge produces two mechanical conflicts, and every named import in its thirty-five new files still resolves against this tree. Importing it costs a day; rewriting it costs weeks and lands somewhere worse.

## What Changes

- **Durable drafts, persisted by the daemon.** A draft is a titled body with a monotonic version, stored under `$PASEO_HOME/drafts/<artifactId>/`. It belongs to no session and survives every restart. The product term is **Drafts**; the code term is `artifact`, because `docs/glossary.md` already spends "draft" on the composer's draft agent tab, `DraftAgentControls`, and review drafts.
- **A Drafts screen**, reachable from the sidebar: create, edit, rename, archive, unarchive, and search. Search covers current bodies and sent revisions, and reports which revision matched.
- **A Scratchpad panel** inside a workspace, so the next instruction can be written while the current one runs. It shows what is planned for this workspace and what has already run here.
- **Autosave with optimistic concurrency.** A 200 ms pause earns a write. Text leaves the queue only once the daemon accepts it, so a failed write has something left to retry, and `saved` is never shown for text that exists only on this machine. A concurrent edit surfaces as a conflict with the record as it now stands, offering reload or overwrite.
- **Declared plans, derived status.** A draft can be planned for several workspaces or, when the worktree does not exist yet, for a project. "Planned here" is derived, never stored: planned for this workspace and the current revision has not been sent here. Sending revision 17 moves the draft to history; editing it afterwards returns it to planned with unsent changes, with nothing for the user to label.
- **Immutable send snapshots.** Each send freezes a byte-exact copy of the body and appends a dispatch record carrying the target agent, workspace, `clientMessageId`, and status. Later edits never rewrite a snapshot. Sending to a new agent and to an existing session share one bridge — the `clientMessageId` Paseo already carries on both paths.
- **Multi-host aggregation.** The list spans every connected host that advertises the capability. Drafts stay on the host that owns them; nothing is synced between hosts.
- **Capability gating.** The whole surface gates once on `server_info.features.drafts`. A daemon that predates `draft.*` reports "this host does not support drafts" — there is no degraded path, per `docs/protocol-compatibility.md`.
- **Two gaps in the imported code are closed as part of this change**, each as its own commit:
  - `onSend` sends without flushing the save loop, so typing and sending inside the debounce window captures the daemon's older body into the snapshot. Send must flush first, and must refuse when the flush fails.
  - Checkpoints are written and cleared but never read back: nothing replays `@paseo:draft-checkpoints` into the editor or the write queue. Unsaved text survives a disconnect within a session (via the source's in-memory overlay) and dies on restart. The editor must recover the checkpoint on mount.
- **Two unrelated commits ride along with the branch** and are taken deliberately: ZCode in the ACP provider catalog, and a desktop fix so an explicit `features.webUi.enabled` opt-in survives the desktop wrapper's default.
- Out of scope: attachments on a draft, scheduled or automatic sending, cross-host draft sync, and templates or variables.

## Capabilities

### New Capabilities

- `durable-drafts`: daemon-persisted prompt drafts — storage and versioning, the Drafts screen, the Scratchpad panel, autosave and conflict handling, plans and derived status, send snapshots and the dispatch log, search, multi-host aggregation, offline checkpoints, and capability gating.
- `zcode-acp-provider`: ZCode offered in the ACP provider catalog, including the host configuration it requires.
- `desktop-web-ui-opt-in`: an explicit web UI opt-in in daemon config survives the desktop wrapper's own default.

### Modified Capabilities

None. This fork's `openspec/specs/` covers only its custom capabilities, and none of them are touched.

## Impact

- **Packages:** `protocol` (new `draft/` schemas, one feature flag), `server` (new `drafts/` store and `session/draft/` handler), `client` (new SDK methods), `app` (new `drafts/` module, screen, panel, route, i18n resource module), `desktop` (web UI opt-in fix).
- **No new dependencies.** The branch touches no `package.json`, so the install footprint and lockfile are unchanged.
- **New daemon storage:** `$PASEO_HOME/drafts/<artifactId>/` with `artifact.json` (mutable), `snapshots/NNNN.json` (write-once), and `dispatches.jsonl` (append-only). No index file is persisted; the search projection is rebuilt in memory at boot. No migrations, matching `docs/data-model.md`.
- **New client storage key:** `@paseo:draft-checkpoints` (AsyncStorage on native, IndexedDB on web), holding only fields still owed to the daemon. Deliberately not the composer's `paseo-drafts` store, whose five-minute expiry and blank-on-clear semantics are wrong for a document.
- **New protocol surface:** nine `draft.*` request/response pairs plus a `draft.artifact_update` push, each mapped to a semantic permission in `operation-permissions.ts`. Changing `packages/protocol` means the zod-aot inbound validators regenerate; `pretypecheck` already does this.
- **Terminology:** `docs/glossary.md` needs an entry that separates the three senses of "draft" now in the codebase — draft agent, composer draft store, and the draft artifact this change adds.

**Overall rebase risk: medium.** Two files conflict on import (`server/session.ts`, `app/workspace-tabs/launcher/index.tsx`) and both resolutions are mechanical. The imported design already minimizes future exposure: the whole `draft.*` domain sits behind one object so `session.ts` never grows a `case`, and `dispatchInboundMessage` must not gain a branch — it sits exactly on the lint complexity ceiling, so a twenty-first branch fails the build. The nine `app` files that register a nav row, a tab kind, and a panel are the standing rebase cost of this change; upstream reshaped nav and launcher registration twice inside the sixty-commit window, and the imported branch already carries two commits that chased those reshapes.
